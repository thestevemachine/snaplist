# Compact listing review and exact seller SKUs

New local and cloud drafts start with an empty seller SKU. Upload and photo-group review no longer ask for a bin/SKU prefix. Assign one exact SKU per item in the listing card, or use the existing first-SKU sequence on the listings page (65-23537, 65-23538, …). No generated letter or random suffix is added. Internal draft/publication identity stays separate. Blank or duplicate SKUs are blocked before publication. Existing saved and published SKUs are never silently renamed; an already-published eBay offer must be corrected on eBay.

Category ID is directly below its category selector with label and ID on one line. Every aspect shows label, value, then collapsed analysis notes. Shipping/returns starts collapsed, including after reloading. Optional product line and quantity/unit fields are omitted from the editor. Pattern is shown only when a meaningful pattern is known; eBay-required fields remain editable.

Thema and Charakter are each supplemented once with five relevant shape/color/style associations when the category supports it. Selection-only fields only receive matching supported options; single-value categories remain single-value. New free-text style associations are marked as suggestions, never dates or fictional-character affiliations. Later seller changes and clears are preserved.

Stored front-photo measurements now fill FREE_TEXT frame-width/height fields even when Taxonomy supplies suggested sizes. Supported aliases map to the actual category field; existing/manual dimensions and explicit clears are preserved. Unavailable geometry/reference data is reported beside the empty field. Reloading, opening cards and style completion never start paid AI requests. No guessed width is fabricated to hide unavailable measurements.

The daily EU database health cron remains unchanged. No changes to ebay-ki-tools.


Each aspect is one group in the DOM: name, control/value, collapsed analysis notes, then a bottom divider. It no longer uses a fieldset legend that could visually separate the heading from its control. Lower collapsed sections have reduced spacing.

Read TITAN/TITANIUM on demo lenses as material evidence with its exact quote and photo index. Titanium translations are accepted only in material facts. Label-proven titanium refines generic metal; a separately supported acetate front remains part of the material selection. Component-specific front/temple material labels can coexist. Display stands/backgrounds are not frame materials or colors. Existing stored label evidence is reused without a new paid call; manual material edits are preserved.

Front-photo ratios use the average of both lens widths/heights. Where a label-proven bridge width is available, check it against the visible gap between the lens contours. A discrepancy above max(3 mm, 20%) flags the reference check as unreliable and prevents automatic copying of those estimates into eBay measurement fields. This is an additional plausibility check, not a calibration guarantee. Investigating a particular inaccurate estimate still requires the original front photo, the size inscription, and calculated values (ideally independently measured comparison dimensions).

Gemini 3.5 Flash-Lite is the default for sorting, listing analysis, cloud drafts and missing-model requests. Explicit existing browser selections remain selectable and are preserved; displayed defaults are persisted so the UI and outgoing requests agree. There is no model upgrade on failure.

Review cards use a wrapping, auto-growing title textarea and a wrapping header; the detail-card switch has a blue border and larger target. The bulk condition selector starts at NEW_OTHER where supported, and unset category conditions use that supported default. The inscription disclosure is smaller, optional MPN and sunglasses magnification fields are omitted, and the verbose water-resistance default note is removed. Sunglasses get grey lenses only when no lens color was supplied and the category allows it; optional magnification is absent (required magnification uses zero when allowed). Recognized oval/pilot shapes use Pilot Oval in generated titles. Model/lens-width inscriptions on demo lenses, including Lindberg model-code/width pairs, are explicitly covered by the existing OCR prompt and evidence parser; missing widths are not invented.

The publication dialog includes a compact list of all nonempty item specifics and condition notes. Per-card reanalysis accepts an optional 500-character seller correction hint, uses existing photos, and retains the existing explicit cost/overwrite confirmation. The hint is classification guidance, not permission to invent inscription evidence. Measurement reference validation and the existing 3 mm trial width offset remain in place.

Eyewear price research now searches brand + model + item type, accepts official eBay.de links, excludes new-with-tags stock when the seller chose NEW_OTHER (condition 1500), and uses item prices excluding shipping. At least three same-model/category candidates with a reasonable price spread are required for a market-backed recommendation. New local drafts adopt that recommendation only while the original listing snapshot is still current, and newly completed cloud drafts import the same recommendation. Existing/manual edits remain protected; there is no bulk repricing. Eyewear recommendations do not receive the generic storewide markup. Unsupported photo-only estimates explicitly target conservative eBay resale prices, never MSRP/optician retail or shop new prices, and remain labelled as unverified when no suitable eBay evidence is available.

Research uses the existing Browse API (active asking prices only). No sold-history access is fabricated. Marketplace Insights is restricted by eBay: https://www.developer.ebay.com/api-docs/buy/static/ref-buy-browse-filters.html . No new third-party service or paid market-data API is introduced.

Titanium now requires an explicit readable material marking or the seller's manual confirmation; a brand such as ic! berlin or a high-confidence visual estimate does not establish the alloy. A deterministic guard changes unsupported generated titanium claims to generic metal in material fields and generated titles. The existing explicit Lindberg shop setting remains unchanged. Existing unposted detail cards apply this guard locally without a paid reanalysis, preserving manual titles/material confirmations and descriptions. Both the initial analysis and category completion reject estimated titanium facts.

New sunglasses analyses also include a clearly labelled approximate total width in the description when the existing front-photo calculation is reliable. This keeps the width available even if the category lacks a width aspect; a custom description template does not discard it. Missing/uncertain geometry and seller-cleared measurements do not invent a width, and manual description text is not rewritten on reload. The existing 3 mm trial deduction is retained.

Material consistency is advisory: a short title/material warning is shown on the card and in publication confirmation, but is excluded from client readiness blockers and server-side Trading validation failures. The seller can proceed with the existing publication confirmation. Real required-field, SKU, price, category, shipping and photo validation remains mandatory. Trading verification/publication responses retain material warnings as warnings.

Titanium selections also include Metall when the category supports a multi-value material field and that value. Existing printed-material mapping no longer strips Metall. For ic! berlin, repeated OCR titanium claims are not accepted automatically even when the model labels its quote as printed: the seller must explicitly confirm titanium through a material edit. This guard runs again after category enrichment to prevent a later AI fill from reintroducing the guess.

The card removes the long reanalysis explanation, classification explanation, duplicated condition-note explanation and dual-category fee paragraph. The two compact disclosures are Aufdrucke & Maße and Maße berechnen; they share a tight wrapper. The aspect section is labelled Artikelmerkmale on one line. Secondary-category display is shortened, while category IDs and actual selections remain available.

Lindberg demo-lens size handling recognizes a complete quoted model/width pair such as LINDBERG 1257 46 without requiring a box or bridge separator. The parser requires Lindberg context and a lens-print fact; it does not apply this pattern to unrelated brands. Scheibenbreite, Scheibengröße and Lens Size map to the canonical lens-width field, remain label-only in AI facts, and normalize an explicit mm suffix. The OCR prompt requests the full demo-lens print and separate model/width facts using 46 mm as the example.

Existing drafts can recover a missing reference from stored label quotes without paying for another model call. Supported empty category aliases are filled; stored contours with pixel calibration can be recalculated using that reference and the existing 3 mm offset. Only earlier derived, estimated values are replaced; manually confirmed/cleared references, manual measurements and descriptions remain intact. If old OCR did not preserve the print, no missing digits are invented. Explicit seller-confirmed lens widths are also accepted as references by the measurement calculation and measurement-only endpoint, with referenceSource=manual rather than a claim of automatic label recognition. Shop defaults and guessed model numbers remain invalid scales.

After a successful publication, only that listing card collapses. Restored posted cards start closed, retain a visible eBay link/status in their header and can be reopened read-only. Verification alone and failed publication attempts do not close the card; other draft cards keep their own open state.

Known validation messages are clickable: exact aspect-name matches and standard title/SKU/price/description/condition/category/shipping/photo warnings resolve to marked local controls. Clicking opens any closed parent disclosure, scrolls to the field and focuses its input. No value is changed or API call started by navigation. Shipping disclosure state follows programmatic opening as well as manual toggles.

Optical frames always show a dedicated Glasbreite (mm) number input outside disclosures, even if no width was recognized or category metadata is absent. Manual values/clears are recorded as explicit seller references and transfer only to real supported category fields; selection-only categories still require an allowed value. Free-text numeric fields remain manually editable even when eBay supplies suggested sizes. A new manual width cannot leave an earlier conflicting width as a stale hidden value. This does not make a missing optional width a publication blocker.
