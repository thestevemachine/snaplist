# Compact listing review and exact seller SKUs

New local and cloud drafts start with an empty seller SKU. Upload and photo-group review no longer ask for a bin/SKU prefix. Assign one exact SKU per item in the listing card, or use the existing first-SKU sequence on the listings page (65-23537, 65-23538, …). No generated letter or random suffix is added. Internal draft/publication identity stays separate. Blank or duplicate SKUs are blocked before publication. Existing saved and published SKUs are never silently renamed; an already-published eBay offer must be corrected on eBay.

Category ID is directly below its category selector with label and ID on one line. Every aspect shows label, value, then collapsed analysis notes. Shipping/returns and optional product line start collapsed. Optional quantity/unit fields are omitted from the editor; eBay-required fields remain editable.

Thema and Charakter are each supplemented once with five relevant shape/color/style associations when the category supports it. Selection-only fields only receive matching supported options; single-value categories remain single-value. New free-text style associations are marked as suggestions, never dates or fictional-character affiliations. Later seller changes and clears are preserved.

Stored front-photo measurements now fill FREE_TEXT frame-width/height fields even when Taxonomy supplies suggested sizes. Supported aliases map to the actual category field; existing/manual dimensions and explicit clears are preserved. Unavailable geometry/reference data is reported beside the empty field. Reloading, opening cards and style completion never start paid AI requests. No guessed width is fabricated to hide unavailable measurements.

The daily EU database health cron remains unchanged. No changes to ebay-ki-tools.
